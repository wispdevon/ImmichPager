# Immich UI parity notes

**Research version 1.4 · 2026-10-22.** Implementation references are pinned to the official Immich **v3.3.3** tag (`d2dac658fe1c67e8bbd08aa18200a32e5d45b9e4`), the reported live baseline. The public demo was observed at **v3.3.4**; the album control and card source files cited below have identical blobs in both tags. [v3.3.3 release](https://github.com/immich-app/immich/releases/tag/v3.3.3) · [v3.3.4 release](https://github.com/immich-app/immich/releases/tag/v3.3.4)

This is a source and screenshot review, not a claim of exhaustive runtime compatibility. A local v3.3.1 fork also includes `Cull photos` navigation work; that fork-only change was excluded. The official tag is the source of truth. Immich v3.3.3 pins `@immich/ui` 0.90.0; Pager retains 0.86.0. The controls used here were compared against 0.90.0 rather than assuming that a matching component name proves matching behavior. Context-menu triggering and navbar active-state behavior match; the later Switch changes do not require a package upgrade because Pager supplies accessible labels and focus styling. Public-demo photographs remain in `/tmp/immichpager-ui-research/` and are not included in this repository. Pager screenshots use the local fixture and NASA images already attributed in `fixtures/photos/README.md`.

To reproduce Pager's browser checks from a clean checkout, use the pinned Node and pnpm versions from `.nvmrc` and `package.json`, then run:

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm build
flock /tmp/immichpager-e2e.lock pnpm test:e2e e2e/management-actions.spec.ts
```

The E2E server starts the fixture on `127.0.0.1:3200`; the lock serializes runs that share that port. For the client-gallery screenshots, run `DEMO_PORT=4300 pnpm dev:demo` in one terminal, then capture from another after it is ready:

```sh
pnpm exec playwright screenshot --browser chromium --viewport-size="1440,900" http://127.0.0.1:4300/page/acme /tmp/pager-acme-desktop.png
pnpm exec playwright screenshot --browser chromium --viewport-size="390,844" http://127.0.0.1:4300/page/acme /tmp/pager-acme-mobile.png
```

For the Immich reference, follow the official [demo instructions](https://github.com/immich-app/immich#demo), open Photos, Albums, and an album detail, and capture at those same two viewport sizes. The public demo can move beyond v3.3.4, so record the version returned by its `/api/server/version` endpoint with any new captures. Do not upload, edit, or share its example photos.

## Applied findings awaiting approval

These findings are implemented in separate review branches and included in the combined candidate. They are not merged into `dev` or released.

1. **Implemented in PR #20 — Semantic link-button contrast (P0 finding).** The [`Create page` anchor](../src/routes/manage/%2Bpage.svelte#L138) is an `@immich/ui` Button with `href`; the global [anchor color rule](../src/app.css#L36-L45) can override the component foreground utility and produce low contrast in the dark fixture. The synthetic before/after image pair shows the management layout at 390px; computed-style checks confirm the contrast finding. [PR #20](https://github.com/wispdevon/ImmichPager/pull/20) places inheritance in the CSS base layer so native component utilities win; enabled primary buttons pass 4.5:1 contrast checks in both themes.
2. **Implemented in PR #25 — Host theme parity.** The editor follows Immich's current host theme, while a page's own Gallery and responsive preview retain their selected theme. See the Host theme row for the versioned source behavior.
3. **Implemented in PR #24 — Compact page actions.** Desktop keeps its action row; phones keep Copy link visible and put Duplicate/Open/Options in the native context menu. E2E covers touch, keyboard, close and navigation races, focus restoration, popup, clipboard, long titles, and 320px overflow.
4. **Implemented in PR #23 — Editor keyboard exit and commit.** Title Enter and description Ctrl+Enter commit; focus returns after editing exits. Escape exits while preserving autosaved values.
5. **Implemented in PR #22 — Host Pages selection state.** The sidebar bridge marks Pages as current while the Pages iframe is open, using Immich's `NavbarItem` route-state and `aria-current` conventions.
6. **Implemented in PR #21 — Client gallery density and type rhythm.** The covers are already square and cropped; the gallery work adjusts density, title/metadata size, group spacing, and focus states while remaining scoped to client pages.
7. **Implemented in PR #21 — Singular counts (P2 finding).** The browse summary now shows “1 album”, “1 of 1 album”, or “1 of 9 albums” as appropriate; item metadata also uses “1 item”. Browser tests cover filtered and unfiltered singular states.

The public-demo screenshots are evidence only; they are not copied into the project because they contain example-library images. The two committed management screenshots are generated from Pager's fixture and are safe to retain.

## Intentional product differences

- Client pages retain their per-page branding, custom CSS, and independent theme, and omit Immich's authenticated sidebar and management actions. Album links open Immich's native shared viewer.
- Header edits autosave to private drafts; explicit publication and its review remain required before changing client-visible content. Escape exits editing while keeping those private edits.
- Selection includes only albums owned by the photographer. Design duplication and appearance files exclude albums, passwords, credentials, and share capabilities.
- Persistent client URLs and password-state guidance follow Pager's publication contract, rather than reproducing Immich collaborators, expiring links, or upload/download settings.

Reference screenshots are read-only observations of the public demo. Mutation, failure, keyboard, and short-height checks use synthetic fixtures; they do not certify an authenticated workflow against the maintainer's installed library. The fixture models the native sidebar and theme contracts, while its header is a simplified development shell. Chromium runtime evidence is complemented by source review; this is not exhaustive browser or screen-reader certification.
