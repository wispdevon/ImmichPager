**Research version 1.3 · 2026-10-22.** Implementation references are pinned to the official Immich **v3.3.3** tag (`d2dac658fe1c67e8bbd08aa18200a32e5d45b9e4`), the reported live baseline. - This branch's management-action before/after captures use fixture page data, not customer content: [`before`](screenshots/parity-management-mobile-before.png) · [`after`](screenshots/parity-management-mobile-after.png).

To reproduce Pager's browser checks from a clean checkout, use the pinned Node and pnpm versions from `.nvmrc` and `package.json`, then run:

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
flock /tmp/immichpager-e2e.lock pnpm test:e2e e2e/management-actions.spec.ts
```

The E2E server starts the fixture on `127.0.0.1:3200`; the lock serializes runs that share that port. For the client-gallery screenshots, run `DEMO_PORT=4300 pnpm dev:demo` in one terminal, then capture from another after it is ready:

```sh
pnpm exec playwright screenshot --browser chromium --viewport-size="1440,900" http://127.0.0.1:4300/page/acme /tmp/pager-acme-desktop.png
pnpm exec playwright screenshot --browser chromium --viewport-size="390,844" http://127.0.0.1:4300/page/acme /tmp/pager-acme-mobile.png
```

For the Immich reference, follow the official [demo instructions](https://github.com/immich-app/immich#demo), open Photos, Albums, and an album detail, and capture at those same two viewport sizes. The public demo can move beyond v3.3.4, so record the version returned by its `/api/server/version` endpoint with any new captures. Do not upload, edit, or share its example photos.

## Ranked parity work

1. **P0 — Semantic link-button contrast.** The [`Create page` anchor](../src/routes/manage/%2Bpage.svelte#L138) is an `@immich/ui` Button with `href`; the global [anchor color rule](../src/app.css#L36-L45) can override the component foreground utility and produce low contrast in the dark fixture. The synthetic before/after image pair shows the management layout at 390px; the contrast finding is confirmed separately by computed-style tests. A separate candidate addresses it and verifies both themes.
2. **Implemented in this branch — Compact page actions.** Desktop keeps its action row; phones keep Copy link visible and put Duplicate/Open/Options in the native context menu. The regression covers touch, keyboard, focus restoration, popup, clipboard, long titles, and 320px overflow.
3. **P1 — Editor keyboard exit and commit.** Restore focus after title/description editing exits and support the source-compatible title Enter and description Ctrl+Enter behavior. Escape exits while preserving autosaved values. Responsive-preview work owns this follow-up.
4. **P1 — Host Pages selection state.** The current sidebar bridge does not mark Pages as current, so the underlying Albums item can stay selected while the Pages iframe is open. Reuse `NavbarItem` route-state and `aria-current` conventions at the host integration boundary.
5. **P1 — Client gallery density and type rhythm.** The covers are already square and cropped; compare two-column 390px cards against Immich's single-column layout, and tune title/metadata size, group spacing, and focus states. Keep the work scoped to the client gallery and test long titles in both themes.
6. **P2 — Singular browse counts.** Use “1 album” and “N albums” in the gallery browse summary; the current “1 albums” text is grammatically incorrect.

The public-demo screenshots are evidence only; they are not copied into the project because they contain example-library images. The two committed management screenshots are generated from Pager's fixture and are safe to retain.
